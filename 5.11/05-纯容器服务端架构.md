# 纯容器服务端架构

## 第一阶段推荐形态

```text
docker compose
  ├─ exam-web        # React/Vite 前端或静态资源
  ├─ exam-api        # Rust API：鉴权、题目、判分、PDF 页图
  ├─ exam-worker     # Rust Worker：导入、翻译、转图、缓存预热
  ├─ reverse-proxy   # Caddy/Nginx/Traefik
  └─ data volume     # 私有 SQLite/PDF/JPG/缓存
```

## 为什么第一版用纯容器

- 不强依赖 Azure SQL 或 Blob。
- 用户可以用容器命令自己安装。
- 当前题库已经是 SQLite，复用成本最低。
- PDF/JPG/SQLite 都适合做普通文件持久化。
- Rust API 和 worker 可以小体积部署。

## 推荐目录结构

```text
/data
  /app
    app.sqlite                 # 用户、ACL、审计、考试记录
  /banks
    /SC-100
      bank.sqlite              # 服务端私有题库，只读打开
      translations.sqlite      # 可选翻译库
      source.pdf               # 服务端私有 PDF
      manifest.json            # 服务端私有 manifest
      /pages
        /base
          page-001-scale2.jpg  # 无水印基础页图
  /cache
    /watermark                 # 短 TTL 水印图
    /jobs                      # 任务临时文件
```

## 核心环境变量

| 环境变量 | 示例 | 说明 |
|---|---|---|
| `EXAM_DATA_DIR` | `/data` | 总数据目录 |
| `EXAM_BANKS_DIR` | `/data/banks` | 题库私有资产目录 |
| `EXAM_APP_DB` | `/data/app/app.sqlite` | 用户、ACL、审计、考试记录库 |
| `EXAM_CACHE_DIR` | `/data/cache` | 页图、水印、任务缓存 |
| `EXAM_PUBLIC_BASE_URL` | `https://exam.example.com` | 对外地址 |
| `OIDC_ISSUER` | `https://login.microsoftonline.com/<tenant>/v2.0` | AAD/OIDC issuer |
| `OIDC_CLIENT_ID` | `<client-id>` | 应用 ID |
| `OIDC_AUDIENCE` | `api://exam-api` | API token audience |
| `AI_PROVIDER` | `none` / `azure-openai` / `openai-compatible` | AI/翻译提供方 |
| `PDF_RENDER_SCALE` | `2.0` | PDF 页图渲染倍率 |
| `PAGE_CACHE_POLICY` | `shared-base-dynamic-watermark` | 页图缓存策略 |

## 数据库策略

第一版：

```text
题库数据：/data/banks/<bank>/bank.sqlite，只读
用户数据：/data/app/app.sqlite，可写
翻译数据：/data/banks/<bank>/translations.sqlite 或 question_translations 表
```

未来升级：

- 用户/ACL/审计可以迁到 Postgres/Azure SQL。
- PDF/JPG/SQLite 制品可以迁到 MinIO/S3/Azure Blob。
- 题库仍可保留 SQLite 作为作者导入、导出和回滚格式。

## 不建议第一版做的事

- 不把 PDF/JPG 直接塞数据库。
- 不把所有题库拆成云数据库后再开始做产品。
- 不把完整 SQLite/PDF 变成公开下载资源。
