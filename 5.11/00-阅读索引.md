# 阅读索引

本目录是 `5.11调研事实.md` 的精简拆分版，只保留最新已经定下来的结论和配置，不保留历史讨论过程。

## 推荐阅读顺序

1. `01-最终结论.md`  
   快速看最终方向。

2. `02-仓库现状与目录约定.md`  
   明确当前哪些目录是权威数据，哪些只是运行时副本或历史兼容。

3. `03-题库生产链路与脚本配置.md`  
   看题库从 PDF/Markdown/AI 生成到 SQLite 的生产链路，以及脚本配置。

4. `04-TauriExam运行时与双模式.md`  
   看 TauriExam 当前运行时数据位置，以及未来作者模式/普通用户模式如何区分。

5. `05-纯容器服务端架构.md`  
   看未来第一版服务端产品的纯容器方案。

6. `06-核心资产保护与API边界.md`  
   看 PDF、SQLite、翻译库如何保护，普通用户为什么只能走 API。

7. `07-交互题模型与UI渲染.md`  
   看 Drag Drop / Hotspot / ordered-list 的统一数据模型和 UI 分支。

8. `08-翻译与PDF缓存.md`  
   看一题一条翻译和服务端 PDF 页图缓存。

9. `09-落地路线.md`  
   看从当前仓库到独立产品的阶段性路线。

10. `10-Tauri应用Web迁移设计注意事项.md`  
   看 Tauri 应用从一开始如何设计，才能更容易迁移到 Web。

## 当前总原则

- 根目录 `question-banks/` 是作者/构建阶段权威题库输出。
- 普通用户不拿完整 PDF、SQLite、翻译库。
- 第一阶段服务端优先用 Rust + 纯容器 + SQLite + 宿主机 Volume。
- Azure SQL / Blob / Container Apps 只作为后续规模化升级路径。
- TauriExam 未来应区分作者/内部本地模式和普通用户在线模式。
