# 落地路线

## 第一阶段：整理当前仓库

目标：让现有工作区边界清楚、脚本更稳定。

要做：

1. 明确 `question-banks/` 是作者权威题库输出。
2. 保留 `%LOCALAPPDATA%/TauriExam/question-banks/` 作为 Tauri 运行时副本。
3. `TauriExam/question-banks/` 只作为开发种子/历史兼容。
4. 旧导入脚本保持 deprecated 标记。
5. 继续用 `scripts/Resolve-Python.ps1` 统一 Python 解析。
6. 为每个题库补 `manifest.json`。
7. 建立统一 `validate-bank` 能力。

## 第二阶段：抽 Rust 核心库

目标：把 Tauri 后端里可复用能力抽出来。

建议拆分：

```text
exam_core
  - SQLite schema/query
  - 判分逻辑
  - interaction model
  - PDF 渲染接口
  - translation model
  - manifest model
```

收益：

- Tauri commands 可以调用。
- Web API 可以调用。
- Worker 可以调用。
- 避免同一套逻辑复制三份。

## 第三阶段：做 Rust API 服务

目标：服务端能私有持有题库，普通用户通过 API 使用。

建议组件：

```text
exam_api
  - OIDC/AAD token 校验
  - bank catalog
  - question API
  - source page API
  - exam session API
  - ACL
  - rate limit / audit
```

第一版数据：

```text
/data/banks/<bank>/bank.sqlite
/data/banks/<bank>/source.pdf
/data/app/app.sqlite
```

## 第四阶段：做 Worker

目标：处理导入、翻译、PDF 页图预渲染。

```text
exam_worker
  - import markdown
  - validate bank
  - build manifest
  - render PDF pages
  - batch translate
  - warm cache
```

## 第五阶段：Tauri 支持双模式

目标：保留本地作者体验，同时支持普通用户在线使用。

```text
local-author: 本地 SQLite/PDF
cloud-user:   登录后调用 HTTP API
```

关键改造：

- `api.ts` 增加 adapter。
- UI 隐藏普通用户不该看到的本地目录能力。
- cloud-user 不下载完整题库。

## 第六阶段：Web 前端

目标：B/S 主产品形态。

复用：

- 当前 React 组件。
- QuestionPanel。
- DragDropQuestion。
- HotspotQuestion。
- 类型定义。

替换：

- Tauri invoke -> HTTP fetch。
- 本地 PDF 渲染 -> 服务端页图 API。
- 本地题库列表 -> 服务端 bank catalog。

## 第七阶段：规模化升级

只有在需要时再做：

- `app.sqlite` -> Postgres/Azure SQL。
- 宿主机 Volume -> MinIO/S3/Azure Blob。
- 单机 docker compose -> 多实例部署。
- 简单日志 -> 完整审计/监控。

## 优先级总结

先做：

1. 目录和脚本治理。
2. Rust 核心库。
3. Rust API。
4. 服务端私有 SQLite/PDF。
5. Web/Tauri 在线访问。

后做：

1. 云数据库。
2. 对象存储。
3. 多实例。
4. C# 管理后台。
5. 复杂企业权限同步。
