# 交互题模型与 UI 渲染

## 当前结论

当前设计不是简单“所有复杂题都变成一种题”，而是：

```text
数据抽象统一：interaction_options + interaction_targets
题型语义保留：hotspot / drag_drop / ordered_list
UI 按语义分支：Hotspot 下拉 / Drag Drop 拖拽 / Ordered 排序
```

## 统一表的含义

`interaction_options` 表示候选项池。

典型字段：

```text
id
question_id
option_text
option_group
is_distractor
sort_order
```

`interaction_targets` 表示目标位。

典型字段：

```text
id
question_id
position
target_label
option_group
correct_option
```

## 旧表的定位

旧表包括：

```text
drag_options / drag_slots
hotspot_options / hotspot_rows
```

它们现在主要是：

- 早期按题型拆出来的兼容表。
- 当前导入器可从 `interaction_*` 自动回填。
- 当前后端在没有统一表时可以 fallback 使用。

不建议未来继续把它们当新主模型扩展。

## 当前 TauriExam 实际逻辑

1. 导入器解析 `Interaction Options` / `Interaction Targets`。
2. 写入 `interaction_options` / `interaction_targets`。
3. 为兼容旧逻辑，必要时回填 `drag_*` 或 `hotspot_*`。
4. Tauri 后端 `get_interaction_model` 优先读取 `interaction_*`。
5. 后端根据 `questions.question_type` 和 Markdown 中 `- Interaction:` 判断表现形态。
6. 前端根据返回的 `interaction.kind` 选择组件和判分流程。

## Hotspot 映射

触发条件：

```text
question_type 包含 hotspot
或 Interaction 是 dropdown_hotspot
```

映射方式：

```text
interaction_options -> 下拉选项
interaction_targets -> rows
kind = hotspot
```

前端组件：

```text
HotspotQuestion
HotspotPracticePanel
```

判分：

```text
每个 row 的 option_id 是否等于 correct_selection / correct_option
```

## Drag Drop 映射

触发条件：

```text
question_type 包含 drag/drop
或 Interaction 是 drag_drop / ordered_list
```

映射方式：

```text
interaction_options -> 可拖拽选项
interaction_targets -> slots
kind = drag_drop
```

前端组件：

```text
DragDropQuestion
DragDropPracticePanel
```

判分：

```text
每个 slot 的 option_id 是否等于 correct_option
```

## Ordered List

`ordered_list` 本质上也可以用 targets 表达。

区别在 UI：

- slots 会带顺序标签。
- 前端表现为排序/放置顺序。
- 数据仍是候选项池 + 目标位。

## 最终口径

未来服务端/API 主模型应以 `interaction_options` / `interaction_targets` 为准。

旧表可以保留：

- 兼容 TauriExam 当前代码。
- 支持旧题库回退。
- 支持过渡期导出。

但不应再围绕每种题型新增一套主表。
